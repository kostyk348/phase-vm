# ⬡ phase-vm

[English](README.md) | Русский

**Обратимая регистровая машина.** Каждая инструкция модифицирует ровно один
destination; все источники остаются нетронутыми и достаточны для её обращения.
Поэтому инверсия всегда вычислима из *текущего* состояния — **без логов, без
чекпоинтов, без единого лишнего байта**. Прогон программы с `--reverse`
отматывает её до последней границы бит-в-бит.

```text
cargo test        # 66 тестов, вкл. property fuzz F⁻¹(F(S)) == S + shrinker
```

## Почему

Манифестный питч звучал так: *«симплектическая VM, где каждая инструкция —
фазовый поворот, и любая программа обратима до машинного эпсилон без единого
байта логов»*. Так не работают ни IEEE-754, ни разрушающие записи. Этот крейт —
**честное ядро** той идеи:

| заявление | реальность, реализованная здесь |
|---|---|
| обратимость до машинного эпсилон | обратимость **на битах/целых** (`u64`); float неинвертируемы и исключены из ISA намеренно |
| никаких логов вообще | без логов **внутри фазы** — источники инструкции *и есть* лог; стирание (`set`/`mset`) — единственная **граница**, платится один раз при вводе |
| бесплатное путешествие во времени | `rev --steps K`, `runrev`, интерактивный `dbg` с `f`/`b` — шаг назад не требует записи |

## Честность / границы применимости

- Обратимо здесь **целочисленное состояние** (`u64`-слова): каждая обратимая
  инструкция — биекция на Z/2^64 с *вычисляемой* инверсией. Это **не**
  «обратимая физика» — ни гамильтонианов, ни симплектических интеграторов, ни
  термодинамических заявлений — и это **не** криптография:
  `расшифрование = обратный прогон` не делает PC1 стойким.
- «Ноль логов» верен **внутри обратимого региона**. Границы (`set`/`mset`) и
  внешне наблюдаемые эффекты — ровно те места, где информация стоит денег
  (формулировка: [docs/isa.md, §8](docs/isa.md#8-boundary-semantics)).
- Каждое заявление в этом README подкреплено тестами репозитория
  (`cargo test`): property-фаззинг `F⁻¹(F(S)) == S` на сгенерированных
  валидных программах, шринкер, проверенный на «посаженных» багах, семантика
  границ/отката, round-trip журнала L3. Матрица трассировки — в
  [docs/isa.md, §9](docs/isa.md#9-what-the-tests-verify-traceability).

## Инвариант

1. Состояние = регистровый файл + линейная память словами (`u64`).
2. Каждая инструкция пишет **один** destination; все читаемые операнды остаются
   нетронутыми и достаточны для обращения → `inverse()` существует для каждой
   небoundary-операции.
3. `set` / `mset` уничтожают значение без источника → **граница**. Верификатор
   (`check`) классифицирует каждый лист как обратимый / границу / нарушение
   алиасинга (`dst == src`, `target == control` не биективны).
4. `rep N … end` — статический sweep-цикл: биекция, повторённая N раз; обратный
   прогон — N проходов обратного тела. Разворачивается лениво стеком джобов —
   циклы на миллион итераций ничего не аллоцируют.

Беннетовское **чистое вычисление** получается само: посчитать в свежую ячейку,
скопировать результат наружу, развернуть временные обратным прогоном.

## Быстрый старт

```bash
cargo build --release
B=./target/release/phase-vm

# verify + property fuzz чисто обратимого ядра

$B check  programs/mixer.phase            # "ЧИСТО обратима"
$B roundtrip programs/mixer.phase --trials 5000   # F⁻¹(F(S)) == S

# proof explorer: обратимые регионы, границы, «почему не инвертируется»

$B explore programs/ledger.phase --mem 8
$B explore programs/mixer.phase

# clean compute: c = a + b, временные развёрнуты в ноль

$B run programs/clean.phase --set r0=5 --set r1=7     # → r2=0xc, temp 0
$B rev programs/clean.phase --set r0=5 --set r1=7     # → ядро развёрнуто, ввод цел

# транзакционный откат памяти (#11): перевод A→B, abort = обратный прогон

$B run programs/ledger.phase --mem 8      # A=993 B=507
$B rev programs/ledger.phase --mem 8      # abort → A=1000 B=500

# шифр PC1 (#12): расшифрование и есть обратный прогон — отдельного алгоритма нет

$B cipher --key 000102030405060708090a0b0c0d0e0f101112131415161718191a1b1c1d1e1f \
          --pt  0123456789abcdeffedcba987654321000112233445566778899aabbccddeeff

# интерактивный отладчик с ходом назад (#9): f/b/g/c/br/p/pm

$B dbg programs/mixer.phase
```

## CLI

| команда | назначение |
|---|---|
| `check` | классификация листьев: обратимые / границы / алиасинг; вердикт "чисто обратима" |
| `explore` | proof explorer: обратимые регионы, границы, «почему не инвертируется» + минимальные контрпримеры |
| `run` | прямой прогон |
| `runrev` | обратный прогон **из заданного состояния** (без прямого) |
| `rev [--steps K]` | прямой прогон, затем откат K листьев (или всего обратимого суффикса) |
| `roundtrip` | property-фаззинг: случайные состояния → `F⁻¹(F(S)) == S` |
| `dbg` | интерактивный отладчик: `f`/`b` шаг, `g N` goto, `c` continue, `br/bl/bd`, `p`, `pm` |
| `bench` | ns/лист вперёд vs назад vs полный снапшот состояния |
| `cipher` | демо PC1: шифрование = прямой прогон, расшифрование = обратный |

Текстовый формат: одна инструкция на строку, `#` — комментарии, регистры
`r0..rN`, немедленные значения в десятичном / `0x…` / `0b…` / отрицательном
виде.

**ISA:** `nop not inc dec xor add sub swp rotl rotr toff cswp` (обратимые) ·
`madd msub mxor rmadd rmsub` (память словами) · `set mset` (границы).

Формальная спецификация, написанная по коду: [docs/isa.md](docs/isa.md) —
состояние машины, пред/постусловия и `inverse` каждой инструкции, таблица
обратимости, семантика границ.

## Измерено (release, i7-класс)

| | цена | доп. память |
|---|---|---|
| reverse | **~6.8 ns/лист, flat** для состояния 64 Б → 1 МБ | **0 Б** |
| forward | ~5.5 ns/лист | 0 Б |
| snapshot (CoW) | 7.8 ns @ 64 Б → 1.9 мкс @ 64 КБ → **25 мкс @ 1 МБ** | полная копия |

**Откат стоит O(сделанных шагов), а не O(байт состояния).** Это измеряемое
ядро обратимой парадигмы — свойство, на котором строятся дальнейшие проекты
(транзакционные хранилища, WAL-less in-memory DB, reverse debugging).

PC1: 12-раундовый ARX-кернел, блок/ключ 256 бит. Лавина измерена на уровне
~0.5 скорости переворота битов; поток инструкций **не содержит
зависящих от данных ветвлений** (нет `cswp`), значит нет зависящего от данных
тайминга на уровне кода.

## Применение: транзакционные батчи с бесплатным откатом

`examples/batch_tx.rs` — паттерн WAL-less in-memory транзакций (`#11`) и
спекулятивных тиков DSO: машина остаётся **чисто обратимой**, хост решает
commit/abort по инвариантам, проверенным *после* применения, abort — это
обратный прогон.

```bash
cargo run --release --example batch_tx
```

Сценарий: 256 счетов, батчи из 16 переводов размером 60–95% баланса
отправителя **на момент сборки батча** — поэтому дважды задействованный
отправитель даёт каскадный овердрафт, невидимый до применения батча. Хост
валидирует после и откатывает весь батч.

```text
пачек OK=12840  откачено=7160 (35.8%)
leaves: fwd=640000  rev(abort)=229120   (15.5 ns/лист)
snapshot-подход скопировал бы 39 МиБ — здесь 0
```

Откат провалившегося батча: **0 байт логов, 0 копий состояния**, а финальное
состояние доказуемо равно эталонной симуляции с commit-only (проверяется
assert).

## Применение: спекулятивное тик-управление с фильтром безопасности

`examples/spec_control.rs` — тик-цикл в духе DSO, где **тик — это фаза**: 7
кандидатов управления за тик *применяются* к состоянию (целочисленный
симплектический Эйлер `v += u; q += v` — честно обратимый шаг по фазе на
целых), валидируются на `|q| ≤ QMAX, |v| ≤ VMAX`, и каждый отклонённый
кандидат откатывается обратным прогоном. Никаких копий состояния между
кандидатами.

```bash
cargo run --release --example spec_control
```

```text
тиков закоммичено=300000  hold=0  возмущений=7500
|q|max=1011 (лимит 3000)  |v|max=60 (лимит 60) — инвариант держался всё время
leaves: fwd=4.8M  rev(отклонённые)=4.2M   (11.8 ns/лист, 106 ms)
финал: q=-2, v=0
MPC-снапшоты скопировали бы 32 МиБ — здесь 0 байт логов/копий
детерминизм: OK (одинаковый seed → одинаковый финал)
```

Zero-trace откат доказывается на каждого кандидата (`assert_eq!` state ==
base после каждого разворачивания); детерминизм доказан двойным прогоном.
Внешние возмущения входят как границы (входы, не откатываются) — ровно как
реальные контуры управления с ними обращаются.

## Применение: фазовый аллокатор (`src/alloc.rs`)

Что обратимость реально даёт аллокатору — и чего не даёт: bump-аллокация уже
обратима (`malloc` = сдвиг указателя), поэтому **откат целой фазы аллокаций к
метке — O(1)** с нулевыми заголовками на объект. `free` в произвольном порядке
без журнала необратим, поэтому это честно ограничено **фазовыми
нагрузками** (тики, транзакции, ECS) — времена жизни объектов кончаются на
границе фазы.

```bash
cargo run --release --example alloc_bench
```

```text
K/фазу      malloc+free  arena+rollback  arena+commit  выигрыш×
8                4.76           1.15           7.93        4.1×
512             14.03           1.08           7.36       12.9×
32768           35.27           1.80           7.56       19.6×
нулевой след отката: OK (offset переиспользован детерминированно)
```

`rollback(mark)` — один `truncate`; цена не растёт с K, а malloc+free
деградирует с ростом K. Фазы в commit-режиме платят один `reset` (O(1)) на
границе. Zero-trace: после отката следующая аллокация детерминированно
переиспользует тот же offset (проверяется).

## L3: журнал решений — управляющий поток по данным, всё ещё обратимый

`src/ctl.rs` (`ifnz rN … end`, `wz rN … end`, `rep N … end`): структурные
ветвления/циклы, чей *журнал решений* — **O(решений), никогда O(состояния)** —
`if` пишет один флаг, `while` — одно число итераций. Reverse доверяет журналу
(LIFO, post-order), `reverse_checked` дополнительно перепроверяет условия.
Прямолинейные листья остаются без логов.

```bash
cargo run --release --example ctl_demo
```

```text
итераций цикла: 500000 (данные! rep статически не смог бы)
журнал: 1 запись = 8 B      (наивный трейс шагов: 8 000 008 B)
forward:  3.7 ns/лист   reverse: 5.7 ns/лист — состояние == граница, журнал пуст
```

Зависящее от данных умножение через `while` на 500k итераций откатывается
одним 8-байтовым решением — измерена аксиома архитектуры «журнал = решения,
никогда состояние».

## P2: AOT — компиляция ядер в нативный код (`src/aot.rs`)

Интерпретатор ~3.7–16 ns/лист; сгенерированный C (`cc -O2 -shared`) + dlopen:

```bash
cargo run --release --example aot_bench
# forward : native 0.06 ns/лист | interpreter 6.08 | 94.8×
# reverse : native 0.09 ns/лист | interpreter 8.21 | 94.9×

```

`phase_fwd`/`phase_rev` повторяют обратимую семантику; native == interpreter
проверяется; `rev` требует чисто обратимого ядра (границы = чекпоинт).

## L4: фазовая капсула в `.eml` (`src/cap.rs`)

Состояние + ядро путешествуют как RFC-5322 конверт: заголовки несут
инварианты (kernel-hash, boundary-hash, state-hash), тело — состояние и
программу. Принимающий хост верифицирует, не доверяя отправителю:
state-hash → reverse → boundary-hash → повторный forward → state-hash.

```bash
cargo run --release --example capsule
# капсула: 612 B · верификация OK · финал после миграции == чистый прогон

```

## P10: широкие лейны AVX2 (`examples/wide_bench.rs`)

Обратимые примитивы (xor/add/rot) покомпонентны → векторизуются. Измерено
AVX2 vs скаляр на обратимых xor+rotl-проходах: корректность проверяется
(AVX2 == скаляр); на x86 автогенератор уже закрывает большую часть разрыва
(~1.3× у ручного AVX2) — широкий выигрыш становится реальным на SoA-кернелах
с несколькими регистрами.

## Парадигма для типовых задач

Не «где прикрутить PHASE к старым программам», а как выглядит обычное
программирование в парадигме (`phase-arch/TYPICAL.md` ставит в соответствие 9
классов типовых задач → фазовую форму → выигрыш):

- **A/B-выбор конфигурации без копий** — `examples/typical_ab.rs`:
  применить кандидата → метрика → откатить проигравшего (обратный прогон,
  4 листа) → закоммитить победителя. 500k раундов, 0 копий состояния
  (классика: 32 МБ клонов), 17 ns/лист.
- **Парсинг с O(1) восстановлением от ошибки** — `examples/typical_parse.rs`:
  каждая запись парсится под свою метку Arena; семантический сбой →
  `rollback(mark)`. 54 515 плохих записей восстановлены 2.6 МБ с 54 515
  O(1)-откатами вместо 327 090 отдельных free.

Паттерн для всех них: аллоцировать в фазе, преобразовывать обратимо,
**валидировать на границе**, закоммитить или откатить. Отказ — ветка
управляющего потока — и для повседневного кода тоже.

## Фазовая математика: обратимые функции с аналитическими инверсиями

`src/pmath.rs` + `examples/math_demo.rs` — обычная математика, переписанная
для парадигмы: внутри фазы математика = набор биекций на Z/2^64, чья инверсия
*вычисляется*, а не хранится: `MulOdd(m)` (нечётный множитель — биекция;
инверсия через Newton mod-inverse), `Add`, `Xor`, `RotL`, ARX-раунды.
Композиции — биекции, поэтому любая формула разворачивается точно
(проверяется на случайных round-trip). Float-математика остаётся на границе
(она неинвертируема).

## Ось B: meet-in-the-middle (`examples/mitm_bfs.rs`)

Двунаправленный BFS на лабиринтах 200×200 (~25% стен): bi расширяет **в 1.6×
меньше** вершин, чем uni (330k против 535k на 40 лабиринтах); длины путей
совпадают (проверяется). Честная формулировка: sqrt-подобное сокращение там,
где существует декомпозиция, а не универсальное обещание 2^N/2.

## Применение: rollback-неткод / серверная реконсиляция

`examples/rollback_netcode.rs` — детерминированный авторитарный тик, где
поздние клиентские вводы исправляются **откатом**, а не снапшотами. Физика =
целочисленный симплектический Эйлер (обратима); вводы — границы, хранимые как
журнал 1 байт/сущность/тик. На поздний ввод, отличающийся от предсказания,
сервер откатывается к тому тику, применяет ввод, пересимулирует
детерминированно.

```bash
cargo run --release --example rollback_netcode
```

```text
реконсиляций: 142253   окно отката 1..8 тиков (откачено 639715 тиков)
память: журнал входов 240 000 B  против снапшотов мира 3 840 000 B (16×)
корректность: hash-цепочка всех 60 001 тиков == эталон (ground truth)
```

Финальная тайм-линия доказуемо равна эталонному прогону без задержки —
hash-цепочка каждого тика-границы совпадает. Это лекарство от
фон-неймановской болезни N3/N4: реконсиляция без снапшотов мира,
запечатанная SINT hash-chain аудитом.

## Честные ограничения

- Обратимая семантика живёт на битах/целых. Округление/NaN по IEEE-754
  неинвертируемы; float вне ISA.
- «Без логов» верно *внутри фазы*. Откат **через** границу `set`/`mset`
  требует чекпоинта — это цена стирания, платится на границе, один раз за
  фазу (см. `dbg`, который отказывается шагать назад через границу без
  одного).
- PC1 — демонстратор парадигмы (`расшифрование = reverse`), **не**
  криптографически аудированный шифр.
- Статический `rep` — зависящий от данных управляющий поток (обратимые
  `if`/циклы) живёт в L3 с журналом решений (`src/ctl.rs`).

## Roadmap / происхождение

POC-1 более широкой программы обратимых вычислений. Кластеры:

- **A core** — этот крейт (`phase-vm`): обратимая ISA, модель границ,
  верификатор, proof explorer. Семена: `#9` отладчик с шагом назад (`dbg`),
  `#11` rollback-транзакции (`ledger.phase`), `#3/#11` семантика
  границ-как-чекпоинтов.
- **C crypto** — `PC1`: ARX-кернел, у которого расшифрование — обратный
  прогон (`#12`).
- Далее: обратимый управляющий поток (в духе Janus), модель кадра/вызовов,
  раундовая функция CA, варианты с постоянным весом.
